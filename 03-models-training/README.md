# Models, GPU, AI Chips, Inference

Конспект для AI Agents Developer. Как модели физически устроены, обучаются и работают.

---

## Часть 1. Что такое модель физически

### Файл с числами

Модель (Claude, GPT, Llama) — это **набор файлов с весами**. Веса — это огромная матрица чисел (тензоры). Это всё "знание" модели.

Формат на диске: `.safetensors` или `.bin`. Внутри — словарь "имя слоя → тензор":

```
embed_tokens.weight        → тензор [vocab_size, hidden_dim]
layer.0.attention.q_proj   → тензор [hidden_dim, hidden_dim]
layer.0.attention.k_proj   → тензор [hidden_dim, hidden_dim]
layer.0.mlp.gate_proj      → тензор [hidden_dim, intermediate_dim]
...
layer.95.mlp.down_proj     → тензор [...]
```

Размеры:
- 7B параметров × 2 байта (fp16) = 14 GB
- 70B × 2 = 140 GB
- 200B × 2 = 400 GB
- Frontier-модели (предположительно 500B-1T+) = 1-2 TB

Сам файл ничего не "делает" — это как `.jar` без JVM.

### Что нужно, чтобы модель ответила

1. **Веса** — файл, загруженный в память
2. **Inference engine** — софт, прогоняющий токены через веса (vLLM, TensorRT-LLM, проприетарные у Anthropic)
3. **GPU/TPU** — железо для матричных умножений

Большие модели не помещаются на одну GPU. Inference распределён через **tensor parallelism** (одна модель на 8/16 GPU, синхронно считающих разные части).

### Аналогия для Java-разработчика

- **Модель (.safetensors)** ≈ скомпилированный .jar
- **Inference engine** ≈ JVM
- **GPU кластер** ≈ железо
- **Inference worker process** ≈ запущенный Spring Boot, держащий jar
- **API gateway** ≈ nginx / API Gateway перед бэкендом

"Claude Opus 4.7" — это набор весов, развёрнутый у Anthropic на GPU-кластере с собственным inference engine, обёрнутом в API gateway. Одного "сервера, где живёт Claude" не существует — это распределённая система.

## Часть 2. Токены

### Зачем нужны

Нейросеть работает с числами. Текст → токены (числа) — это **токенизация**.

**Subword tokenization** (Byte-Pair Encoding) — компромисс:
- Частые слова → 1 токен
- Редкие → разбиваются на части
- Словарь обычно 50K-200K токенов

### Пример

`"Андрей работает Java-разработчиком в Стамбуле"` → ~10 токенов:
- "Андре" → #45821
- "й" → #98
- " работает" → #19283
- " Java" → #16634
- "-" → #12
- "разработ" → #87291
- ...

**Важные наблюдения:**
- Пробелы — часть токена
- Английские слова часто целиком — 1 токен
- Русский дробится на больше токенов → API дороже для не-английского
- Числа, эмодзи — по своим правилам

### Цифры для оценки

- **Английский:** ~1 токен на 4 символа, ~1.3 токена/слово
- **Русский:** ~1 токен на 2 символа, ~2-3 токена/слово
- **Код:** часто эффективнее естественного языка

Контекст 200K токенов ≈ 80K русских слов ≈ 500-700 страниц A4.

### Как генерируется ответ

Модель **не пишет слова**, она **предсказывает следующий токен**.

1. Контекст → токены → векторы (embeddings)
2. Forward pass через все слои → распределение вероятностей по словарю
3. Sampling: выбор следующего токена (детерминированно или с температурой)
4. Токен добавляется в конец, цикл повторяется
5. Stop-token или лимит → конец генерации

### Эмбеддинги ≠ токены

- **Токен** — дискретный ID (целое число)
- **Эмбеддинг** — непрерывный вектор, представляющий смысл

Embedding model (text-embedding-3-large и др.) — отдельный класс моделей, берёт текст и возвращает один вектор для семантического поиска / RAG.

## Часть 3. Inference (запуск модели)

### Что это

Inference — **запуск уже обученной модели** для генерации ответа. Веса не меняются, никакого обучения. Только прогон.

### Базовый цикл

1. **Токенизация** — текст в числа
2. **Embedding** — каждый токен в вектор размерности тысячи
3. **Forward pass** — через все слои трансформера (десятки/сотни слоёв), матричные умножения + attention + нелинейности
4. **Output** — распределение вероятностей по словарю
5. **Sampling** — выбор следующего токена
6. **Цикл** — токен дописывается, повторить
7. **Stop** — специальный токен или лимит

### Ключевые свойства

- **Stateless между запросами.** Модель ничего не помнит после ответа. Истории диалога подаются обратно как часть нового input'а.
- **Каждый токен — отдельный forward pass.** Ответ из 1000 токенов = 1000 прогонов.
- **Batching.** GPU обслуживает не один запрос, а десятки параллельно — повышает эффективность железа.
- **Reasoning меняет картину** — модель сначала тысячи thinking-токенов, потом финальный ответ.

### KV-cache

**Оптимизация** для устранения квадратичной сложности генерации.

При генерации нового токена K и V тензоры из attention для предыдущих токенов **не меняются**. Логично их **запомнить** и не пересчитывать.

**Свойства:**
- Живёт в **VRAM GPU** (не Redis, не диск!)
- Внутри одного inference-запроса
- Размер: ~2.6 MB на токен для 70B-модели
- Контекст 100K на 70B = ~260 GB KV-cache (больше самих весов)

Без KV-cache длинные контексты были бы невозможны.

**Prefix caching / Prompt caching** — переиспользование KV-cache между запросами с общим префиксом (system prompt, шаблонные сообщения). Anthropic так оптимизирует cached tokens — ~10x дешевле обычных input.

## Часть 4. AI-чипы

### Иерархия

**AI-чип** — любой кремний, оптимизированный под нейросетевые вычисления. GPU — частный случай.

**Классы:**

1. **GPU** (Nvidia H100/B200, AMD MI300X/MI355X) — универсальный, мощная экосистема CUDA
2. **TPU** (Google) — systolic array, только тензорные операции, в Google Cloud
3. **NPU** — потребительские устройства (Apple Neural Engine, Qualcomm Hexagon)
4. **Custom ASIC** — AWS Trainium/Inferentia, Microsoft Maia, Meta MTIA, Groq LPU, Cerebras
5. **FPGA** — устаревает для AI

### Топовые GPU (на май 2026)

**Nvidia:**
- **B200** (Blackwell) — 192 GB HBM3e, ~8 TB/s bandwidth. Стандарт нового деплоя.
- **GB200 Superchip** — 2× B200 + Grace CPU, общая память 384 GB GPU + 480 GB CPU
- **H200** — 141 GB HBM3e (апгрейд H100 80 GB)
- **H100** — 80 GB, workhorse 2023-2024

**AMD:**
- **MI355X** — до 288 GB HBM3e (рекорд VRAM на карте)

**Google TPU:** v5p, v6e (Trillium), v7 (Ironwood, до 192 GB)

### На уровне ноды

- **DGX B200** — 8× B200 = 1.5 TB HBM, NVLink 5 (1.8 TB/s между картами)
- **GB200 NVL72** — 72× B200 + 36 Grace CPU в стойке, 13.5 TB HBM, выглядит как одна виртуальная GPU. Цена — миллионы долларов.

### Кластеры

- **xAI Colossus** — ~200k H100/H200, планы на 1M
- **Microsoft / OpenAI Stargate** — сотни тысяч ускорителей, $500B
- **Meta** — миллионы H100/B200 эквивалентов
- **Anthropic** — AWS Trainium + TPU + Nvidia

### AWS Trainium

Собственный AI-чип AWS, противовес зависимости от Nvidia.

- **Trainium2** (GA декабрь 2024) — 96 GB HBM3, 16 чипов на ноду, UltraServer на 64 чипа
- **Inferentia** — отдельная линейка для inference, дешевле
- Архитектурно ближе к TPU (systolic array), не CUDA
- Стек **AWS Neuron SDK** (компилятор neuronx-cc, runtime, PyTorch/JAX)
- **Anthropic — главный клиент Trainium**, строят Project Rainier на сотни тысяч чипов
- Цена: 30-50% дешевле эквивалентной Nvidia-конфигурации

### Почему Nvidia монополист

- Зрелая экосистема CUDA (18+ лет)
- Под неё написаны PyTorch, vLLM, TensorRT
- AMD ROCm, Trainium Neuron — догоняют по софту
- Производит TSMC на 4nm/3nm — ограниченные мощности
- HBM делают 3 компании (Samsung, SK Hynix, Micron) — узкое горлышко

## Часть 5. Training (обучение)

### Жизненный цикл модели

1. **Pre-training** — модель читает гигантские объёмы текста (15-20T токенов), учится предсказывать следующий токен. Основная фаза, требует месяцев работы кластера.

2. **Post-training** — несколько этапов на улучшение поведения:
    - **SFT** (Supervised Fine-Tuning) на curated данных
    - **RLHF** (RL from Human Feedback)
    - **Constitutional AI** (у Anthropic) — модель критикует свои ответы по принципам
    - **Safety training, red-teaming**

3. **Reasoning training** (новое, с 2024) — отдельный RL-этап на верифицируемых задачах (математика, код), модель учится длинным цепочкам рассуждения.

### Сколько памяти нужно для training

Соотношение **training memory : inference memory** обычно **6-8x**.

На каждый параметр в памяти GPU нужно:

```
Weights (BF16):        2 bytes
Gradients (BF16):      2 bytes
Adam momentum (FP32):  4 bytes
Adam variance (FP32):  4 bytes
─────────────────────
Total:                 12 bytes/param (без активаций)
```

Плюс **активации** (промежуточные результаты forward pass для backward) — сравнимо или больше.

### Конкретные цифры

| Модель | Inference (BF16) | Training (full) |
|---|---|---|
| 7B | 14 GB | 80-110 GB |
| 70B | 140 GB | 800-1000 GB |
| 405B | 810 GB | 5-7 TB |

**Реальные тренинги:**
- Meta тренировала Llama 3.1 405B на **16,000 H100 одновременно**
- xAI для Grok 3 — ~**100,000 H100**
- Frontier модели — десятки/сотни тысяч GPU, месяцы работы

### Виды обучения по затратам

- **Full pre-training с нуля** — $100M-$1B+, уровень корпораций
- **Continued pre-training** — добавление данных к существующей модели
- **Fine-tuning** — дообучение, требований меньше
- **LoRA / QLoRA** — только небольшие адаптеры поверх замороженных весов, можно на одной consumer GPU

## Часть 6. Как модель учится медицине и психологии

### Слой 1 — откуда знание

На этапе **pre-training** модель просто читает огромные корпусы. По медицине/психологии туда попадает:

- **Научные статьи** — PubMed (~36M публикаций), bioRxiv, medRxiv, открытые журналы
- **Учебники** — медицинские учебники, психиатрические руководства, фармакологические справочники
- **Клинические гайдлайны** — UpToDate, NICE, ВОЗ, AMA, APA, DSM-5, ICD-11
- **Wikipedia, Mayo Clinic, NIH MedlinePlus, Merck Manual**
- **Образовательные сайты** — Khan Academy, медицинские школы
- **Форумы** — Reddit (r/medicine), Quora, Stack Exchange

**Без участия врачей** — это unsupervised learning. Модель просто предсказывает следующее слово.

Результат: модели уровня Claude/GPT-4 сдают **USMLE** (медицинский экзамен США) на проходной балл уже с 2023.

### Слой 2 — где участвуют врачи и психологи

Сырое знание не равно правильному поведению. На **post-training** этапах:

**a) SFT на curated данных**
- Эксперты-медики пишут **эталонные ответы** на типичные запросы
- "У меня болит грудная клетка", "Друг говорит, хочет покончить с собой", "Побочки сертралина"
- Тысячи пар вопрос-ответ → модель файнтьюнится

**b) RLHF (Reinforcement Learning from Human Feedback)**
- Модель генерирует несколько вариантов ответа
- Аннотаторы-эксперты ранжируют: лучший / приемлемый / плохой / опасный
- На рейтингах обучается **reward model** (отдельная нейросеть)
- Базовая модель оптимизируется через RL с reward model как сигналом
- Прямо размечено тысячи примеров, **косвенно экспертиза обобщается** на миллионы новых генераций

**c) Constitutional AI (Anthropic-specific)**
- Формулируется набор **принципов**: "будь честен", "не давай вредных советов", "признавай ограничения в медицине"
- Модель сама критикует свои ответы и переписывает по конституции
- Эксперты участвуют в формулировании принципов

**d) Red-teaming**
- Психологи симулируют пользователей в кризисе → проверяют ответы на suicide ideation, расстройства пищевого поведения, психотические состояния
- Врачи задают каверзные вопросы — попытаются ли получить опасные советы
- Найденные слабости идут в новые training rounds

### Слой 3 — continuous evaluation

После релиза:
- A/B тесты новых версий с доменными экспертами
- Бенчмарки (MultiMedQA, MedQA, MedMCQA)
- Анализ продакшен-логов (на агрегированном уровне)
- Реагирование на инциденты

### Что важно понимать

**Никто не сидит и не проверяет каждый твой диалог.** Это невозможно физически. Эксперты влияют на модель **через training data**, и их вклад потом распространяется через generalization.

**Модель ≠ замена специалиста.** Модель имеет огромный breadth знаний, но:
- Нет клинического суждения
- Не видит пациента
- Не знает контекст (анамнез, аллергии)
- Не несёт юридической ответственности
- Не может назначить обследования

Поэтому Anthropic специально учит модель **не позиционировать себя как врача**: дать информацию, не диагностировать, рекомендовать обратиться к специалисту.

### Ограничения подхода

- **Bias обучающих данных** — большая часть медлитературы на английском, западная медицина
- **Knowledge cutoff** — гайдлайны после cutoff неизвестны без поиска
- **Hallucinations** — модель может уверенно выдать неправильный факт (название препарата, дозировку)
- **Скейл экспертизы** — эксперты размечают тысячи примеров, не покрывают всё пространство запросов
- **Конфликты в литературе** — разные школы, страны, изменения с годами

## Часть 7. Цены на токены

### Формирование цены

1. **Стоимость железа** — амортизация GPU + электричество + датацентр
2. **Размер модели** — больше параметров = больше GPU на запрос
3. **Output dorоже input в 3-5x** — input батчуется параллельно (prefill), output генерируется последовательно (decode)
4. **Reasoning токены = output токены** — thinking может в 50-100x увеличить стоимость запроса
5. **R&D амортизация** — $100M-$1B на тренировку флагмана
6. **Маржа** — компании пока убыточны на масштабе, цены субсидированы инвестициями
7. **Конкурентное давление** — за последние 2 года цены упали в 10-20x за тот же уровень качества

### Себестоимость vs цена (оценки SemiAnalysis)

- **Sonnet-class**: себестоимость ~$1-2/M output, цена $15/M
- **Opus-class reasoning**: себестоимость $20-50/M output, цена $60-75/M

### Тренд

- Цены за **тот же уровень качества** продолжат падать в 5-10x за пару лет
- Цены за **frontier-модели текущего момента** останутся $10-50/M output
- Reasoning токены подешевеют с новыми архитектурами (MLA из DeepSeek, новые формы attention)

## Часть 8. RAM-кризис 2026 (контекст индустрии)

Важно понимать, как AI-бум влияет на индустрию шире:

- AI-GPU обвешана **HBM-памятью** (high-bandwidth memory)
- HBM производят те же 3 компании, что обычную RAM (Samsung, SK Hynix, Micron)
- **1 GB HBM = 3-4 GB производственной мощности обычной DRAM**
- Маржа HBM в 5x выше — производители переключились
- 93% производства памяти ушло в HBM для AI-датацентров
- Цены на DDR5 выросли на 100-200% за квартал
- Micron закрывает consumer-бренд Crucial
- Новые фабрики придут только в 2027-2028

Следствие: **дороже не только GPU, но и RAM, и SSD**. Hetzner и аналоги повышают цены.

## Ключевые выводы для собеседования / работы

1. **Модель = файл с весами + inference engine + GPU.** "Сервера, где живёт Claude" не существует — это распределённая система.

2. **Inference stateless.** Между запросами модель ничего не помнит — каждый раз подавать полную историю.

3. **Токены — валюта индустрии.** Всё считается в токенах: цены, лимиты, скорость. Русский в 2-3x дороже английского.

4. **KV-cache живёт в VRAM GPU**, не в Redis. Может занимать больше памяти, чем сами веса.

5. **Training требует в 6-8x больше памяти**, чем inference той же модели.

6. **AI-чипы ≠ только GPU.** TPU, Trainium, Cerebras, Groq — альтернативы со своими стеками.

7. **Anthropic стратегически зависит от AWS Trainium** (Project Rainier).

8. **Знание медицины модель получает из текстов**, поведение — через post-training с экспертами.

9. **Модель не заменяет специалиста** — нет клинического суждения, ответственности, контекста.

10. **AI-бум физически вытесняет производство обычной RAM** — это надо учитывать при планировании инфраструктуры.
