# Claude как агент: Reasoning и Tool Use

Конспект для AI Agents Developer. Что современный Claude умеет встроенно, без надстроек.

---

## Часть 1. Reasoning (рассуждение)

### Что такое reasoning

Reasoning — это способность модели **прийти к ответу через цепочку логических шагов**, а не выдать его одним прыжком.

**Контраст:**
- **Recall** (нет reasoning): "Когда родился Бах?" → "1685". Модель просто извлекает факт.
- **Reasoning:** "Если поезд А вышел в 8:00 со скоростью 60 км/ч, поезд Б в 9:30 со скоростью 90 км/ч — во сколько Б догонит А?" → нужно построить уравнение, решить, проверить.

Reasoning нужен когда:
- Ответ не существует в обучающих данных дословно — его надо вычислить
- Задача многошаговая
- Нужно держать промежуточное состояние
- Нужно рассмотреть варианты, отбросить неверные
- Нужно проверить свой же ответ

### Chain-of-Thought (CoT) — базовый механизм

Открытие 2022 года (Wei et al., Google): если попросить LLM "думать шаг за шагом" — качество reasoning'а драматически растёт.

**Почему работает:** LLM генерирует токены последовательно, каждый следующий зависит от всех предыдущих. Если модель сначала сгенерирует промежуточные шаги — у неё в контексте появляются результаты, на которые она опирается дальше. Это как дать человеку карандаш и бумагу вместо требования считать в уме.

**Без CoT** (модель отвечает сразу): часто ошибается на нетривиальной арифметике, путается в логике.

**С CoT** (модель рассуждает вслух): на тех же задачах точность вырастает в разы.

То есть **reasoning у LLM физически реализован как генерация дополнительных токенов**. Чем больше "думает" — тем больше промежуточных токенов, тем точнее финальный ответ.

### Reasoning models — новый класс

С сентября 2024 (OpenAI o1) появился новый класс — **reasoning models** (thinking models). Это не просто LLM с promted CoT, а модели, специально обученные через RL **дольше и качественнее рассуждать**.

Текущие представители: o1, o3, Claude Opus 4.7 / Sonnet 4.6 с extended thinking, DeepSeek R1, Gemini 2.5 Thinking.

**Чем обучение отличается:**

1. **RL с верифицируемыми наградами.** Берут задачи, где правильность ответа проверяется автоматически: математика, код (есть тесты), логические задачи. Модель генерирует длинные цепочки, награждается за корректные ответы.

2. **Emergent behaviors.** В процессе RL у модели сами появляются полезные привычки: "стоп, проверю предыдущий шаг", "попробую другой подход", "это не сходится, начну заново". Не запрограммировано — модель сама обнаружила полезность.

3. **Test-time compute scaling.** Главное открытие: **качество растёт не только от размера модели, но и от количества compute на inference**. Это новая ось масштабирования.

**Reasoning vs prompted CoT:**
- Обычная LLM с CoT — рассуждает поверхностно (несколько предложений), не возвращается при ошибке
- Reasoning model — тратит тысячи/десятки тысяч токенов, исследует альтернативы, замечает ошибки, перепроверяет

### Extended Thinking в Claude

У Claude reasoning реализован через специальные **thinking blocks**. В API:

```json
{
  "model": "claude-opus-4-7",
  "thinking": {"type": "enabled", "budget_tokens": 20000},
  "messages": [...]
}
```

Модель перед финальным ответом генерирует отдельный блок типа `thinking`, в котором свободно размышляет.

**Что происходит внутри thinking-блока:**
- Декомпозирует задачу
- Рассматривает варианты ("Подход 1... Подход 2... Сравню...")
- Замечает ошибки ("Стоп, в шаге 3 допустил неточность")
- Перепроверяет
- Планирует tool calls

**Свойства thinking-токенов:**
- Видны в response (отдельный content block)
- Стоят как обычные output-токены
- Часть thinking-content'а Anthropic шифрует для безопасности
- Generation latency растёт пропорционально budget'у

### Когда reasoning помогает, когда нет

**Помогает:**
- Математика, код, научные задачи
- Multi-step планирование
- Debugging, code review
- Critical reasoning, где важна точность

**Не помогает или вредит:**
- Recall-задачи ("когда родился Бах")
- Короткие ответы ("как переименовать переменную")
- Creative writing без логических ограничений
- Тривиальные вопросы

Поэтому Anthropic сделал thinking опциональным и регулируемым по budget'у.

### Reasoning vs CoT vs ToT vs Reflection

- **Reasoning** — общее свойство: способность думать по шагам
- **Chain-of-Thought** — конкретный паттерн: линейная цепочка
- **Tree of Thoughts** — дерево вариантов с pruning'ом
- **Reflection / Reflexion** — самокритика и переписывание ответа
- **Reasoning models** — модели, обученные делать всё вышеперечисленное **внутри весов**, без внешней обвязки

**Главный практический вывод:** когда у тебя reasoning-модель, отдельные обвязки типа Reflection и ToT часто избыточны — модель применяет эти стратегии сама в thinking. Сложность из application layer переехала в model layer.

## Часть 2. Tool Use в Claude

### Базовый примитив

Tool use в Claude — это нативная способность, обученная в весах. Модель умеет:

- Решать, когда нужен tool, а когда отвечать текстом
- Формировать корректные параметры по JSON-схеме
- Понимать tool_result и продолжать рассуждение

### Параллельные tool calls

В одном assistant-turn модель может вернуть **сразу несколько `tool_use` блоков**, которые runtime может выполнять параллельно.

Раньше было строго последовательно: tool → результат → tool → результат. Теперь модель может сказать "мне нужны данные из A и B одновременно" — runtime выполняет оба параллельно, возвращает оба результата следующим turn'ом.

Это критично для performance агентов: запросы в independent источники не блокируют друг друга.

### Tool choice control

API позволяет управлять, как именно модель выбирает tool:

- `auto` — модель сама решает (default)
- `any` — модель **обязана** вызвать хотя бы какой-то tool
- `{name: "X"}` — модель должна вызвать именно tool X
- `none` — нельзя вызывать tools

Используется для форсирования поведения (например, обязательно классифицировать через classifier-tool перед ответом).

### Streaming tool use

`tool_use` блоки приходят постепенно через streaming. Можно начинать выполнение tool ещё до завершения генерации финального ответа. Снижает perceived latency.

## Часть 3. Agentic Loop (нативная агентская работа)

### Что это

Claude обучен не "вернуть один ответ", а **работать в цикле**:

```
[модель планирует] → [tool call] → [tool result] → 
[модель оценивает результат] → [следующий tool call] → ...
[модель решает: задача выполнена] → [финальный ответ]
```

### Что модель делает в цикле

- **Держит длинный план в голове** и возвращается к нему после сотен tool calls
- **Перепланирует** при провалах ("этот подход не работает, попробую другой")
- **Останавливается, когда задача решена** — нетривиальная способность, многие модели зацикливаются
- **Просит уточнения** у пользователя, когда reasonably stuck

Это поведение видно в Claude Code: говоришь "пофикси баг", агент сам читает файлы, гипотезирует, бежит тесты, фиксит, повторяет. Никакой внешней оркестрации типа LangGraph не нужно — цикл управляется самой моделью.

### Sub-agents / orchestration

Нет встроенного "spawn child agent" примитива, но есть паттерн **main agent делегирует подзадачи специализированным sub-agents**. Под капотом — рекурсивные вызовы Claude с отдельным контекстом для каждой подзадачи.

Anthropic использует этот паттерн в research-агенте: planner-агент декомпозирует задачу, запускает N research sub-агентов параллельно, агрегирует результаты.

В API это пишется руками (N параллельных вызовов с разными промптами), но качество модели позволяет надёжно строить.

## Часть 4. Дополнительные встроенные возможности

### Computer Use

Claude умеет управлять компьютером "как человек" через скриншоты и эмуляцию мыши/клавиатуры. Специальный tool `computer`:
- `screenshot` — увидеть экран
- `click at (x, y)` — кликнуть
- `type 'hello'` — ввести текст
- `key press` — нажать клавишу

База для:
- Browser-агентов (Claude in Chrome)
- RPA-сценариев
- UI-тестирования
- Desktop-агентов (Cowork)

### Memory / Context Management

**Memory tool** — модель работает с долгосрочной памятью через специальный tool (читает/пишет notes). Сама решает, что запомнить между сессиями.

**Context editing** — в длинных agentic циклах можно автоматически удалять старые tool results из контекста, чтобы не упереться в context window.

**Search past chats** — в продуктовом Claude есть retrieval по предыдущим разговорам с инъекцией в system prompt.

### Code Execution и Files

В Claude.ai встроены:
- **Code execution** — Python-сэндбокс, модель запускает код, обрабатывает данные
- **File creation** — генерация docx/xlsx/pptx/pdf
- **Artifacts** — изолированная среда для React/HTML, рендерится в чате

С точки зрения API — это built-in tools (`bash_tool`, `str_replace`, `create_file`, `view`).

### Prompt Caching

Не алгоритм агентности, но критичная инфраструктурная фича. Длинные system prompts с tools, документацией, контекстом — **кешируются на стороне Anthropic**. Повторные вызовы платят только за дельту.

Цены на cached tokens — в ~10x ниже обычных input-токенов. Без этого длинные agentic loops были бы экономически неподъёмными.

## Часть 5. Чего Claude НЕ делает встроенно

Чтобы было понимание границ:

- **Нет встроенного planner'а как отдельной стадии** — планирование происходит внутри thinking, не как отдельный pipeline-компонент. Если нужен явный plan-execute-replan цикл — пишется снаружи.

- **Нет встроенного RAG** — retrieval из vector DB строишь сам через tools или MCP. Модель не имеет встроенной "базы знаний" кроме training data.

- **Нет встроенного multi-agent orchestration framework** — нет аналога CrewAI/AutoGen. Сложные графы агентов с условиями переходов — снаружи.

- **Нет встроенного long-running task primitive** — если задача требует часов работы, ты сам управляешь чекпойнтингом, восстановлением, очередями.

## Часть 6. Линейка моделей и выбор для задач

Текущая линейка (2026):
- **Claude Opus 4.7** — флагман для сложных reasoning-задач, критичных решений
- **Claude Sonnet 4.6** — workhorse, оптимальный баланс цена/качество
- **Claude Haiku 4.5** — лёгкие subroutines, классификация, роутинг

### Правила выбора

**Opus 4.7:**
- Сложный reasoning (математика, архитектура, debugging)
- Критичные решения (финансы, безопасность)
- Multi-agent оркестратор/планировщик

**Sonnet 4.6:**
- Большинство production-задач
- Tool use в сложных пайплайнах
- Code generation, code review
- Дешевле Opus в ~3-5x, качество близко

**Haiku 4.5:**
- Классификация транзакций
- Routing между агентами
- Простые трансформации текста
- Когда важна низкая latency и стоимость

**Когда включать extended thinking:**
- Reasoning-tasks где важна точность
- Не включать для лёгких задач — лишняя latency и токены

## Ключевые выводы для собеседования / работы

1. **Reasoning — это обученная способность модели**, не prompt-трюк. Современные reasoning models применяют CoT/ToT/Reflection внутри thinking-блока эмерджентно.

2. **Test-time compute scaling — новая ось масштабирования.** Качество растёт не только от размера модели, но от количества compute на inference.

3. **Tool use нативный, не надстройка.** Модель обучена на структурированном tool use, JSON-схемах, agent loops.

4. **Параллельные tool calls — снижают latency агента.** Запросы в независимые источники не блокируют друг друга.

5. **Agentic loop управляется моделью**, не внешней оркестрацией. Claude Code — пример: один Claude в цикле без LangGraph.

6. **Computer use — отдельный tool, открывающий browser/desktop агентов.**

7. **Prompt caching обязателен для production agent'ов** с длинным system prompt.

8. **Внешние обвязки (Reflection, ToT) часто избыточны для reasoning моделей.** Сложность переехала из application layer в model layer.

9. **Выбор модели важнее обвязки.** Haiku 4.5 для routing'а, Sonnet 4.6 для основных задач, Opus 4.7 для критичного reasoning'а.
